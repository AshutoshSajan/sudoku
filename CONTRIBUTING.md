# Contributing to Sudoku

## Branching & releases (the production flow)

- `main` is always deployable. Never commit to it directly.
- `dev` is the integration branch.
- Every feature, bugfix, or chore gets its own branch **from `dev`**:
  `feature/<name>`, `bugfix/<name>`, `hotfix/<name>`.
- Open a PR **into `dev`**. After review, `dev` is promoted to `main`
  via a second PR. Tag releases on `main` as `vX.Y.Z`:

```sh
git checkout -b feature/awesome-thing dev
# ... work, commit, push ...
gh pr create --base dev --title "feat: awesome thing"
# after merge:
gh pr create --base main --head dev --title "Release vX.Y.Z"
git tag vX.Y.Z origin/main && git push origin vX.Y.Z
```

## Commits

Commits **must** follow [Conventional Commits](https://www.conventionalcommits.org/)
(`type(scope): subject`) — the changelog generator depends on it, and the
local hook enforces it:

```sh
git config core.hooksPath .githooks   # one-time setup per clone
```

Types: `feat` `fix` `docs` `style` `refactor` `perf` `test` `build` `ci`
`chore` `revert`. Merge commits are exempt.

## Changelog

`CHANGELOG.md` is generated by [git-cliff](https://git-cliff.org) from
`cliff.toml`:

- **CI path (preferred):** on every push to `main`, CI regenerates and commits
  it automatically.
- **No-CI fallback:** the `.githooks/post-merge` hook regenerates it locally —
  review the diff and commit it yourself.

Preview locally: `git cliff --unreleased`.

## Checks before every PR

```sh
flutter analyze
flutter test
```

CI runs both on every push and PR.

## Publishing the browser extensions

Release builds of the popup extension live in `extension/` (sources only —
`extension/app/` is generated, see `extension/README.md`).

- **Chrome Web Store:** set repo secrets `CHROME_EXTENSION_ID`,
  `CHROME_CLIENT_ID`, `CHROME_CLIENT_SECRET`, `CHROME_REFRESH_TOKEN`, then
  uncomment the `publish-chrome` job in `.github/workflows/ci.yaml`.
- **Firefox AMO:** set secrets `AMO_API_KEY`, `AMO_API_SECRET`, then uncomment
  the `publish-firefox` job. Use `--channel listed` for public listing,
  `unlisted` for self-distributed signed `.xpi`.
- Manual fallback (no CI): follow `extension/README.md`
  (`web-ext sign` / store upload by hand).
